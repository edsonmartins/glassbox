Debug não deveria ser um jogo de adivinhação entre você e a IA.

Hoje, quando você pede ajuda para debugar, a IA recebe texto morto — logs, stack traces, fragmentos de código copiados e colados. Ela não tem acesso ao estado real do programa. Não pode inspecionar variáveis. Não pode avaliar expressões. Ela adivinha.

Glassbox muda o paradigma: a IA recebe acesso direto ao debugger via MCP. Ela vê o que está acontecendo em tempo real. Inspeciona. Avalia. Diagnostica. Propõe o fix exato. Tudo enquanto você observa cada passo na TUI.

Transparência total. Daí o nome: Glassbox — o oposto de blackbox.

Arquitetura

Como funciona por dentro

glassbox/
├── mcp-server/                ← TypeScript, MCP SDK oficial
│   ├── index.ts                  Entrypoint JSON-RPC via stdio
│   ├── tools.ts                  15 tools MCP registradas
│   └── handlers/
│       ├── lifecycle.ts           launch, attach, disconnect
│       ├── control.ts             continue, step_over, step_into
│       ├── breakpoints.ts         breakpoint, catch, conditional
│       └── inspection.ts          locals, inspect, evaluate, stack
│
├── debug-core/                ← API unificada sobre backends
│   ├── core.ts                   Interface abstrata de debug
│   ├── backends/

│   │   ├── jdb-backend.ts        v0.1 — JDB via child_process (JDWP)
│   │   ├── dap-backend.ts        v0.3 — DAP protocol (Python, Go, Rust...)
│   └── event-stream.ts         Eventos tipados JSON para TUI/Web
│
├── tui/                       ← Rust + Ratatui (futuro)
│   ├── main.rs                   TUI rica no terminal
│   ├── panels/                   Source, Variables, Agent, Events
│   └── modes.rs                  Autônomo, Manual, Colaborativo
│
└── web-ui/                    ← React (futuro)
    └── GlassboxUI.jsx            Dashboard web equivalente à TUI
MCP Tools

15 tools. Uma API.

A IA chama tools MCP padronizadas. Cada tool executa um comando de debug e retorna JSON estruturado.

Quick Start
